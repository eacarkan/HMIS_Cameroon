# Commercial Protection Note

**Project:** SIGH/DME (HMIS/EMR) — Phase 1 pilot-core foundation
**Status:** Draft for mentor review · **Date:** 2026-06-28

## Defined party
In this note, **the Provider** means the **Provider / Software and Digital Architecture Lead** — the proposing party. The final contracting legal entity is **to be confirmed in the written mandate** and is not fixed by this document.

## Confidentiality
This package and the accompanying demonstration are **confidential**. They are shared **solely for technical review and a controlled demonstration** to the Ministry of Public Health (MINSANTE). They may not be redistributed, reproduced, or disclosed to third parties without the written consent of **the Provider**.

## No intellectual-property or source-code transfer
Nothing in this package transfers any intellectual property or source code. The demonstration shows running behaviour on fake/demo data; it does **not** convey rights to the source code, build tooling, or underlying implementation.

## No full technical / security architecture disclosure
This package does **not** disclose the full technical architecture, security architecture, deployment topology, or supplier strategy. Such disclosure, where appropriate, would occur only under a written mandate and an agreed confidentiality framework.

## No full financial-model disclosure
This package does **not** include the detailed financial model or the detailed budget breakdown. Any post-acceptance maintenance and operation (O&M) would be the subject of a **separate optional service contract** and is **not** part of the implementation package or its stated value.

## No procurement / award implication
This package and the demonstration do **not** constitute a tender response, a commitment to contract, or any procurement award, and create no expectation thereof.

## No acceptance implication
The demonstration does **not** constitute acceptance, production authorization, or authorization to process real patient data. Acceptance and real-data use follow a separate organizational process (**Gate 7**) under MINSANTE authority.

## Condition for deeper disclosure
Any deeper technical or financial disclosure — including full architecture, security design, deployment topology, supplier strategy, or financial model — requires, beforehand:
1. a **written mandate** from MINSANTE to proceed;
2. a **confidentiality protection** instrument; and
3. an agreed **contractual / reimbursement framework**.

## Reservation of rights
All rights are reserved by **the Provider**. No licence is granted by this package except the limited right to review it for the purpose of the controlled demonstration described herein.
